## 2. 先准备代码、环境和数据

以下命令在 Linux / WSL 的项目根目录执行，需可用的 NVIDIA CUDA GPU。Mac 负责管理代码、文档及提交材料；本指南不支持在 Mac 上复现 CUDA 训练。

```bash
git clone https://github.com/Kreouu/glaucoma.git
cd glaucoma
git switch -c reproduce/384-seed43 0064d2d659b89ea12647862ed4bd855f0ad97353
conda create -n glaucoma python=3.12.13 -y
conda activate glaucoma
python -m pip install -r glaucoma-environment-freeze.txt --extra-index-url https://download.pytorch.org/whl/cu128
python -m pip check
python -c "import torch, torchvision; print(torch.__version__, torchvision.__version__); assert torch.cuda.is_available(); x=torch.randn(32,32,device='cuda',requires_grad=True); x.square().mean().backward(); torch.cuda.synchronize(); print(torch.cuda.get_device_name(0), 'CUDA backward PASS')"
```

本节复现B0基线，使用 `glaucoma-environment-freeze.txt`。仓库另有 `glaucoma-swinv2-environment-freeze.txt`，它是后来在同一个conda环境内安装 `timm==1.0.22` 及依赖后的完整快照，用于SwinV2实验；两份txt不代表创建了两个conda环境，也不要求依次安装。新机器按复现目标选择清单，原基线复现按本节命令即可。

参考环境：Python 3.12.13、PyTorch 2.10.0+cu128、torchvision 0.25.0+cu128、CUDA runtime 12.8、cuDNN 9.10.2、RTX 5060 Ti。上面的 CUDA 检查是入门检查，完整训练/重载才是本任务的运行验收。

## 4. 完整复现：从公开 ImageNet 权重重新训练

这才是复现完整训练过程。无须使用我们训练出的 checkpoint 作为起点。

下载的是 torchvision `EfficientNet_B0_Weights.IMAGENET1K_V1` 对应的原始文件：

```bash
mkdir -p pretrain_model
curl --fail --location https://download.pytorch.org/models/efficientnet_b0_rwightman-7f5810bc.pth -o pretrain_model/efficientnet_b0_rwightman-7f5810bc.pth
sha256sum pretrain_model/efficientnet_b0_rwightman-7f5810bc.pth
```

预期文件大小 21,444,401 bytes，SHA-256：

```text
7f5810bc96def8f7552d5b7e68d53c4786f81167d28291b21c0d90e1fca14934
```

来源、上游许可及再分发核对材料见仓库 `licenses/efficientnet_b0/核对说明.md` 和同目录保留文件；训练时保留原始权重不改写，分享材料时一并保留许可与来源。上述材料不等于主办方单独出具的许可批准。

正式训练，不加 `--train-limit` / `--valid-limit`：

```bash
python train.py \
  --data-root datasets/glaucoma_first \
  --output-dir outputs/reproduce_384_w3_seed43 \
  --pretrained-path pretrain_model/efficientnet_b0_rwightman-7f5810bc.pth \
  --epochs 5 --batch-size 16 --size 384 --workers 4 \
  --jpeg-draft --lr 0.0001 --pos-weight 3 --seed 43

python validate.py --run-dir outputs/reproduce_384_w3_seed43
```

输出目录必须尚不存在；重跑请换新目录名。可以在 tmux 中直接运行。当前脚本保存最佳 AUROC checkpoint，不保存每个 epoch 的独立权重，也不支持从中断 epoch 续训。

固定细节：AdamW、weight_decay=0.01、AMP FP16、训练加权 BCE，验证 BCE 不加权；JPEG draft 解码，RGB，等比例缩放并黑边填充至 384，ImageNet 均值/标准差，训练仅水平翻转 p=0.5；不使用年龄，推理阈值 0.5，无 TTA。以仓库源码及运行生成的 config 为准。

原机器每次 5 epoch 约 19 分钟，另外加重载验证时间。先核对配置和验证指标，再比较耗时；硬件不同不能保证逐位相同的训练结果或相同模型文件哈希。即使重新训练产生相近指标，新的 checkpoint 哈希也应单独记录。

若需复核多种子稳定性，用同一命令分别改成 seed 42、43、44，且每次换输出目录。历史参考：

## 5. 384 单张推理耗时与一致性核验

2026-10-28 已在 WSL 的 RTX 5060 Ti 上实测 seed 43 最佳 checkpoint：

| 项目 | 结果 |
|---|---:|
| 计时图 / 预热图 | 100 / 5 |
| 重复轮数 / batch size | 3 / 1 |
| 三轮平均延迟 | 18.093 / 18.654 / 15.979 ms |
| 总平均单图延迟 | 17.5752629231 ms |
| 不一致图数 | 0 |
| 最大概率差 | 0 |

样本为当前验证集 CSV 前 100 张，另取第 101–105 张预热；不是官方指定计时图片。模型只初始化一次，预热不计入，计时包含读图、CPU 预处理、传入 GPU、模型前向、后处理和单行 CSV 写入/flush，并做 CUDA 同步；不包含模型加载、进程启动、冷启动和磁盘 fsync。重复读取可能命中系统文件缓存。

一致性对照同 checkpoint 新生成的 batch=1 参考预测，检查概率误差、分类标签和相对排序。**这仅证明当前机器与这些样本上的表现，官方 T4 / 指定图片的 ≤100 ms 核验尚未完成。**

原始本机产物位于 `outputs/inference_384_seed43_001/`，其中 `submission.csv` 只有 100 张验证图的预测，不能作为测试集提交。轻量报告与逐图耗时在 `docs/evidence/384_seed43_local_timing/`。

队友可自行创建同样的验证样本，不需要接收图片副本：

```bash
python - <<'PY'
import csv
from pathlib import Path

root = Path('datasets/glaucoma_first')
out = Path('outputs/timing_samples_384')
out.mkdir(parents=True, exist_ok=False)
with (root / 'valid.csv').open(newline='') as f:
    rows = list(csv.DictReader(f))[:105]
paths = {p.name.casefold(): p.resolve() for p in (root / 'valid').iterdir() if p.is_file()}
for folder, selected in [('pictures_100', rows[:100]), ('pictures_5', rows[100:105])]:
    dest = out / folder
    dest.mkdir()
    for row in selected:
        path = paths[row['Image_name'].casefold()]
        (dest / path.name).symlink_to(path)
with (out / 'input.csv').open('w', newline='') as f:
    writer = csv.writer(f)
    writer.writerow(['Image_name'])
    writer.writerows([r['Image_name']] for r in rows[:100])
PY

python predict.py \
  --checkpoint outputs/shared_r384_seed43/best.pt \
  --input-csv outputs/timing_samples_384/input.csv \
  --images-dir outputs/timing_samples_384/pictures_100 \
  --output outputs/timing_samples_384/reference.csv

python cost.py \
  outputs/timing_samples_384/reference.csv \
  outputs/timing_samples_384/pictures_100 \
  outputs/timing_samples_384/pictures_5 \
  --checkpoint outputs/shared_r384_seed43/best.pt \
  --output-dir outputs/timing_samples_384/cost
```

若核验自己重训的模型，将两条命令的 checkpoint 路径都换成新的 `best.pt`。输出文件/目录不得已存在；保留 `reference.manifest.json`，cost 会检查它和源码、checkpoint 的哈希。

## 6. 两人如何接着做

先共同完成第 3 节，再让队友完成第 4 节单种子训练，确认能独立跑通全链路。复现完成后分方向：例如一人学习率调度、一人 EMA；每项先只改一个因素，以同一 384 / w3 基线比较，并使用相同的 42、43、44 三个种子。具体方法实现前再约定，避免两人重复跑同一实验。

代码通过各自分支与 PR 合并；每个实验交付配置、代码版本、逐 epoch 指标、最佳验证预测、重载结果、checkpoint 哈希。大权重通过队内共享目录或独立文件传输；Git 保留代码、环境、文档和轻量证据。不需要把整个项目和数据反复压缩发送。

共用现有训练/验证划分；用验证集比较实验，测试集仅用于固定模型的最终推理。由一人统一记录和提交平台 CSV，避免重复提交与文件版本混淆。保留已评分旧版及本次 384 基线，优化结果另建目录。
