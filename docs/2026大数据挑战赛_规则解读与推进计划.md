## 1. 要完成什么

训练一个模型，为每张眼底照片输出青光眼阳性概率，生成可评分的 `submission.csv`；同时准备能够重现这些预测的模型、代码、推理耗时脚本和合规材料。最低完成标准是：**数据无泄漏、CSV 有效、模型来源合规、预测可复现、指定环境下大小和耗时达标、全部材料按时提交。**

建议路线：先用通用图像预训练的小型分类模型跑通全流程，再处理类别不平衡和提高分辨率；最后才考虑集成、自监督或蒸馏。剩余时间有限，先建立可提交版本更重要。

任务、赛程和平台要求见[官网赛题页](https://www.ncccu.org.cn/index/Paper/case2.html)。合规和核验按[参赛规则](./参赛规则.pdf)及[10月27日补充规则](./补充规则.pdf)执行；书面规则和正式补充说明优先于赛题页、FAQ、群聊及口头解释。

本计划建议第一版保留官方验证集。以训练集拟合年龄缺失值处理、年龄标准化等参数；在验证集上比较方案，不对测试集拟合均值、标准差、类别比例或阈值。测试集只用于固定流程的最终推理及规定的运行/耗时核验，不能拿排行榜反馈反复挑模型或调参数。

### 4.2 推理、TTA和集成

- 推理必须固定参数、`eval()`、关闭随机增强，不能更新梯度或归一化参数。
- 允许固定的TTA和多模型集成，但需要把全部前向、预处理和后处理纳入耗时，实际加载的权重计入大小。
- 补充说明允许利用官方患者分组元数据进行固定的同患者预测聚合，但不能据测试汇总信息拟合参数。
- 当前CSV没有显式患者ID，不能把相邻文件编号或相同年龄自行当作同一患者。第一版不做患者平滑；若后续使用，应先核对官方分组依据及计时方式。

依据：[参赛规则](./参赛规则.pdf)第5—8条；[补充规则](./补充规则.pdf)第七—九节。

### 4.3 评分到底优化什么

官网规定主要指标为AUROC，主要指标相同时才比较AUPRC。补充说明进一步规定：AUROC按后台小数保留4位后转百分制显示，主指标展示值相同才比较同样保留4位的AUPRC；仍相同则较早提交者优先。[官网指标说明](https://www.ncccu.org.cn/index/Paper/case2.html)、[补充规则第十节](./补充规则.pdf)。

实践上应保存每张验证图像的连续概率，优先比较AUROC，同时记录AUPRC、召回率和特异度。降低分类阈值能改变召回率及Pred_Label，但不能直接改善概率排序，因此不能把调低阈值当作提升AUROC的方法。

## 5. 按什么顺序实施

### 第一步：建立独立CUDA环境

建议新建 `glaucoma` 环境，保持已有环境完整。官方复测环境为 Python 3.12、PyTorch 2.10.0、torchvision 0.25.0、CUDA 12.8、cuDNN 9，GPU为T4 16GB，CPU 8核、内存32GB。[官网环境要求](https://www.ncccu.org.cn/index/Paper/case2.html)。

下面是后续安装参考，**本次未执行**：

```bash

~/miniconda3/envs/glaucoma/bin/python -m pip install \
  torch==2.10.0 torchvision==0.25.0 \
  --index-url https://download.pytorch.org/whl/cu128
~/miniconda3/envs/glaucoma/bin/python -m pip install \

```

版本配对与CUDA安装命令来自[PyTorch官方版本页](https://pytorch.org/get-started/previous-versions/)。WSL驱动由Windows提供，不应为了安装PyTorch而在WSL内另装Linux显卡驱动，见[NVIDIA WSL指南](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)。

验收：`torch.cuda.is_available()` 为True，识别5060 Ti；真实跑一次分类模型前向、loss反向和优化器更新，无架构或CUDA错误；记录版本及依赖锁定文件。仅看到nvidia-smi不能算这一阶段通过。

### 第二步：做数据审计并固定验证流程

1. 核对训练和验证CSV的文件映射、重复文件名、坏图、标签合法性、年龄缺失值。
2. 检查训练与验证图像的完全重复；如有疑似患者泄漏，记录并建立可信内部验证方案，不能凭文件编号推断患者。
3. 统计训练图尺寸和宽高比，抽看训练/验证正负样本，确定不会裁掉关键眼底区域的预处理。
4. 保留官方验证集，固定随机种子，记录训练清单和验证清单。
5. 测试集不参与上述数据分布分析和超参数选择，只验证最终输入/输出完整性。

验收：形成数据审计报告和固定划分；能够用少量训练数据跑通一轮，并在完整验证集计算AUROC/AUPRC。

### 第三步：完成单模型基线与首次有效提交

建议候选为 torchvision 的 **EfficientNet-B0通用ImageNet权重**，替换为一个二分类logit；这只是起步方案，不代表已核验最终权重许可证或已证明效果最佳。官方文档列出该模型约529万参数，原始分类权重约20.5MB，便于控制资源预算。[模型文档](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.efficientnet_b0.html)。

下载前核对具体权重来源、完整许可证、可再分发权利及预训练数据证据；保留原始预训练权重并计算SHA-256，不可只用代码仓库许可证代替权重许可调查。

起步配置建议：

| 项目 | 建议 |
|---|---|
| 输入 | 先256×256；保持眼底内容，使用固定缩放/填充方案，先验证再考虑裁剪 |
| 训练 | 单logit + BCEWithLogitsLoss，AdamW，AMP混合精度 |
| Batch size | 从16或32试跑，按显存实测调整 |
| 数据加载 | num_workers=4起步，按需读图，不整库缓存 |
| 不平衡 | 先普通BCE基线，再单独比较加权BCE或过采样 |
| 增强 | 适度翻转、旋转和颜色扰动，验证其效果；避免强裁剪损坏关键结构 |
| 模型选择 | 完整验证集AUROC优先，同时保存AUPRC及每图概率 |
| 训练周期 | 先计时短跑，再按验证表现设早停；不预先承诺固定小时数 |

训练集负正比例约30，不意味着 `pos_weight` 必须取30。过采样和大权重同时使用可能过度强调阳性，第一轮对照实验每次只改一种不平衡策略。

验收：保留最佳checkpoint、配置、日志、验证预测和权重哈希；固定推理方案后生成并检查首个CSV，按平台要求提交，保存回执。模型应通过验证集选定，不能根据测试分数回头选择checkpoint。

### 第四步：按收益逐项改进

建议只做下面几组可解释对照，每个实验都记录验证指标、速度、显存与文件大小：

1. 普通BCE vs 加权BCE vs 过采样，其他设置一致。
2. 256输入 vs 384输入，判断更多细节是否改善验证结果。
3. 图像模型 vs 加入Age的小型分支。年龄预处理只在训练集拟合；推理是否允许/如何传入CSV元数据，应核对官方运行接口后确定。
4. 单次推理 vs 固定水平翻转TTA，验证提升是否值得增加耗时。
5. 时间允许再比较第二个轻量骨干或不同种子的固定集成。

第一阶段不建议直接做大型模型、多折多模型集成、自监督或蒸馏。它们虽然部分合规，但增加训练、许可证材料和T4耗时核验成本。仅在已有可提交版本且验证收益明确时再投入。

不要根据测试集预测分布“修正阳性比例”，不要使用测试图生成伪标签。所有集成权重、阈值、预处理和精度在训练/验证阶段确定并冻结。

### 第五步：核验速度、大小和可复现性

**速度按主办方T4测量，5060 Ti上的结果不能证明达标。** 在本机先筛掉明显过慢方案，尽早在T4及官方软件版本复测，或使用主办方提供的核验渠道；本次没有进行T4测试。

根据[参赛规则第7条](./参赛规则.pdf)，`cost.py` 应：

1. 导入并调用与 `predict.py` 相同的模型加载和推理函数。
2. 模型加载、初始化、5张预热图的耗时不计入。
3. 对主办方指定100张图，batch=1串行、连续运行3轮。
4. 每图计时覆盖读取图片、预处理、GPU前向、后处理和写出结果；涉及CUDA时正确同步，避免只测到异步提交时间。
5. 先算每张图3轮均值，再算100张均值，要求不超过100ms。
6. 输出推理精度、平均耗时及与最终CSV的一致性核验结果。

参考调用：

```bash
python cost.py submission.csv pictures_100 pictures_5
```

开发时可用验证图检查计时程序，但不能将其当成官方指定100张样本的最终结果。必须计入最终实际使用的TTA、集成及后处理。

[补充规则第九节](./补充规则.pdf)要求核验100张预测：二值判定及概率排序完全一致，不一致张数为0；在此基础上概率绝对差不超过1e-3。不能认为“误差小于1e-3就一定合格”，因为排序改变也会不合格。规则提及Gate，但网页CSV示例只有三列；没有正式模板要求时不要自行添加Gate列。

超时处置：≤100ms正常认定；100—150ms范围内且大于100ms时，可限期优化实现后复测一次；大于150ms不安排整改复测。整改不能更换已提交模型权重或任意改变结果，因此应在生成最终CSV之前固定FP16等推理精度。

大小口径：最终实际加载的全部模型权重，以及推理config、统计量、类别表和实际调用引擎等必要文件，解压后合计≤500MB；不是整个ZIP必须≤500MB。不参与推理的训练产物、代码和依赖环境不计入该口径，但上传限制仍需看后台。建议为容量和速度都留出余量。

### 第六步：生成CSV、打包并确认提交

网页示例格式为：

```csv
Image_name,Probability,Pred_Label
test_00000.jpg,0.92,1
test_00001.jpg,0.12,0
```

文件名 `submission.csv`，UTF-8；Probability为标签1的概率，Pred_Label默认阈值0.5。真实文件应覆盖5855张测试图，不包含示例假数据。[官网提交要求](https://www.ncccu.org.cn/index/Paper/case2.html)。

提交前检查：

- 三列名称与平台模板一致，不写pandas索引列。
- 文件名不丢失、不重复、不额外增加，建议遵循官方test.csv顺序。
- 概率有限且处于[0,1]，无NaN/Inf；类别仅0或1，与声明阈值一致。
- 保留足够概率精度，不四舍五入为两位小数，不提交硬标签作为概率。
- CSV绑定生成它的checkpoint、精度、配置及代码版本，各文件计算SHA-256。
- 保留每次提交回执和对应模型，核验包里的CSV按附录A对应历史最高分CSV，且必须有完整可复现模型。
